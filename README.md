# 🦊 ربات هوش مصنوعی روباه — سروش‌پلاس

ربات **رسمی** سروش‌پلاس (با توکن Bot API) برای اجرا در **Termux اندروید**؛ بدون نیاز به کامپیوتر یا سرور پولی.

> وضعیت فعلی: منوی اصلی + فرایند کامل «سفارش ساخت ویدیو» (انتخاب مدل و مدت، پرداخت کارت‌به‌کارت، ارسال رسید و بررسی مدیر) فعال است.
> هنوز هیچ API تولید ویدیویی متصل نیست؛ مدل‌ها فقط گزینه انتخابی‌اند و انجام سفارش بعد از تأیید مدیر، دستی/در مراحل بعد است. ربات ادعا نمی‌کند ویدیو خودکار تولید می‌شود.

## دروازه قوانین (اولین شروع)

در اولین `/start`، ربات **عکس قوانین** (`assets/rules.jpg`) را در یک پیام واحد همراه دکمه شیشه‌ای **«✅ تأیید قوانین»** می‌فرستد. تا وقتی کاربر این دکمه را نزند:

- هیچ منو و کیبورد اصلی‌ای برای او باز نمی‌شود؛
- هیچ‌کدام از دکمه‌های منو و دکمه‌های شیشه‌ای کار نمی‌کنند و فقط عکس قوانین دوباره/هشدار تأیید نمایش داده می‌شود.

به‌محض تأیید، تأییدیه در دیتابیس کاربر (`rules_accepted`) ذخیره می‌شود (با ری‌استارت ربات از بین نمی‌رود) و پیام خوشامد با منوی اصلی ارسال می‌شود.

## منوی اصلی

بعد از تأیید قوانین، با `/start`، `/menu` یا ارسال کلمه «منو»، پیام خوشامدگویی زیر با کیبورد اصلی نمایش داده می‌شود:

> 🦊 به ربات هوش مصنوعی روباه خوش آمدید!
> از منوی زیر، سرویس موردنظر خود را انتخاب کنید.

| ردیف | دکمه‌ها |
|---|---|
| ۱ | ساخت تصویر · ساخت ویدیو |
| ۲ | سفارش‌های من · دریافت اعتبار رایگان |
| ۳ | نمونه‌ها · ارتباط با پشتیبانی |
| ۴ | گروه روباه · کانال روباه |

کیبورد از نوع واقعی **Reply Keyboard** (`ReplyKeyboardMarkup` در Bot API رسمی سروش‌پلاس) است؛ یعنی زیر کادر پیام کاربر نمایش داده می‌شود، نه به‌صورت متن یا دکمه Inline.

رفتار فعلی دکمه‌ها:

| دکمه | پاسخ فعلی |
|---|---|
| ساخت تصویر | عکس روباه نقاش (`assets/image_hero.jpg`) + معرفی Bold و انتخاب نوع/مدل و ارسال پرامپت یا عکس |
| ساخت ویدیو | شروع فرایند سفارش ویدیو (پایین‌تر) |
| سفارش‌های من | نمایش سفارش‌های واقعی کاربر از دیتابیس + شناسه شش‌رقمی او |
| دریافت اعتبار رایگان | عکس کارت هدیه (`assets/free_credit.jpg`) + موجودی اعتبار روزانه (۵۰ اعتبار = ۵ عکس) |
| نمونه‌ها | «به زودی ...» |
| ارتباط با پشتیبانی | از کاربر می‌خواهد پیامش را بنویسد؛ پیام همراه مشخصات کامل کاربر برای مدیر می‌رود و مدیر با ریپلای روی همان پیام جواب می‌دهد تا ربات پاسخ را برای همان کاربر بفرستد |
| گروه روباه | عکس روباه (`assets/fox_group.jpg`) با دکمه لینک‌دار «🦊 ورود به گروه روباه» |
| کانال روباه | متن «🦑 : کانال اصلی انجمن روباه» با دکمه «@ai_fox» |

## نصب و اجرا در Termux

### ۱) نصب پیش‌نیازها (فقط بار اول)

```bash
pkg update && pkg install python git
```

### ۲) دریافت پروژه

```bash
git clone https://github.com/splusesupor-oss/ai_new_plus.git
cd ai_new_plus
```

### ۳) ساخت فایل تنظیمات و واردکردن توکن

توکن را از **BotFather سروش‌پلاس** (`splus.ir/botfather`) بگیرید، بعد:

```bash
cp .env.example .env
nano .env
```

داخل `.env` فقط مقدار `BOT_TOKEN` را وارد کنید. در صورت تمایل، نشانی پشتیبانی و لینک گروه/کانال را هم می‌توانید پر کنید (اختیاری):

```env
BOT_TOKEN=توکن-ربات-شما
SUPPORT_CONTACT=
FOX_GROUP_URL=
FOX_CHANNEL_URL=
```

> ⚠️ توکن را در کد، اسکرین‌شات، پیام یا گیت‌هاب منتشر نکنید. فایل `.env` در `.gitignore` است و روی گیت نمی‌رود.

### ۴) اجرا (یک دستور)

```bash
bash run.sh
```

`run.sh` وابستگی‌ها را (در صورت نیاز) نصب می‌کند و ربات را اجرا می‌کند. برای توقف، `Ctrl+C` بزنید.

اجرا به روش دستی هم ممکن است:

```bash
pip install -r requirements.txt
python main.py
```

> نکته Termux: برای اینکه با بستن ترموکس ربات متوقف نشود، می‌توانید از `termux-wake-lock` (از بسته `termux-api`) یا اجرای داخل `tmux` استفاده کنید. خود پروژه برای اجرا به هیچ سروری نیاز ندارد.

## ساخت تصویر با اعتبار روزانه

با «ساخت تصویر»، عکس روباه نقاش (`assets/image_hero.jpg`) و متن معرفی که کاملاً **Bold (توپر)** است و دکمه‌های شیشه‌ای، همه در **یک پیام واحد** (عکس با همان متن به‌صورت کپشن) ارسال می‌شوند:

1. **نحوه تولید:** «تولید تصویر»، «ویرایش تصویر»، «تغییر چهره»
2. **مدل:** «GPT 6»، «flash pro 3»، «nano banana pro»، «fox plus 6»
3. **ارسال محتوا:** در «تولید تصویر» فقط متن؛ در «ویرایش/تغییر چهره» عکس **همراه با متن (کپشن)** لازم است (عکس بدون متن پذیرفته نمی‌شود).
4. سفارش مستقیم و بدون پرداخت برای مدیر می‌رود.

**اعتبار روزانه:** هر کاربر هر روز بر اساس تاریخ تهران (ریست نیمه‌شب ساعت ۱۲ شب) ۵۰ اعتبار رایگان می‌گیرد؛ هر سفارش تصویر ۱۰ اعتبار هزینه دارد (۵ عکس در روز). دکمه «دریافت اعتبار رایگان» عکس کارت هدیه (`assets/free_credit.jpg`) را با متن «شما 50 اعتبار رایگان برای ساخت 5 عکس دریافت کردید» و موجودی فعلی می‌فرستد. اگر اعتبار تمام شود، ابتدا پیام تمام‌شدن اعتبار و راهنمایی صبر تا نیمه‌شب می‌آید. اگر مدیر سفارش تصویر را رد کند (`irj:<id>`) ۱۰ اعتبار برمی‌گردد.

مدیر با «🎨 ارسال تصویر نهایی» (`idl:<id>`) عکس نهایی را می‌فرستد تا همان عکس برای کاربر ارسال و سفارش `completed` شود، یا با `irj:<id>` آن را رد می‌کند. این دکمه‌ها فقط برای مدیر کار می‌کنند.

**وضعیت سفارش عکس** (در «سفارش‌های من» و پیام مدیر) با ویدیو فرق دارد و هرگز «در انتظار پرداخت» نیست: تا تحویل عکس «**در انتظار ارسال عکس**» و اگر مدیر رد کند «**رد شد**». رد کردن نهایی و کامل است: وضعیت `rejected` می‌شود، ۱۰ اعتبار برمی‌گردد، به کاربر صریحاً پیام «سفارش تصویر شما رد شد» می‌رود و سفارش ردشده دیگر با ارسال دیرهنگام عکس قابل تحویل/تکمیل نیست. در دستور «سفارش‌های در انتظار» مدیر هم سفارش‌های عکس با دکمه‌های مخصوص خودشان (`idl/irj`) می‌آیند، نه دکمه‌های تأیید/رد پرداخت ویدیو.

> مدل‌های تصویر هم مثل ویدیو فعلاً گزینه‌های انتخابی سفارش‌ساز هستند؛ تولید خودکار تصویر نیازمند اتصال API رسمی تولید تصویر است و تقلید نمی‌شود.

## پشتیبانی، گروه، کانال و نمونه‌ها

- **ارتباط با پشتیبانی:** بعد از کلیک، ربات دقیقاً می‌نویسد «پیام خودتون رو برای پشتیبانی بنویسید». پیام بعدی کاربر (متن یا عکس) همراه نام، یوزرنیم، کد شش‌رقمی و شناسه سروش‌پلاس او برای مدیر ارسال می‌شود و یک کد پیگیری (`SUP-<id>`) می‌گیرد. مدیر کافی است روی همان پیام **ریپلای** کند و جواب را بفرستد؛ ربات پاسخ (متن/عکس/ویدیو) را برای همان کاربر ارسال می‌کند. اتصال پاسخ به کاربر هم با شناسه پیام مدیر و هم با کد پیگیری در دیتابیس (`support_messages`) ذخیره می‌شود و با ری‌استارت ربات از بین نمی‌رود.
- **گروه روباه:** عکس روباه (`assets/fox_group.jpg`) با دکمه لینک‌دار «🦊 ورود به گروه روباه» (`https://splus.ir/joingroup/AI_hfuzaN9GGKPWF0MsDJg`).
- **کانال روباه:** متن «🦑 : کانال اصلی انجمن روباه» و زیر آن دکمه «@ai_fox» (`https://splus.ir/ai_fox`).
- **نمونه‌ها:** «به زودی ...»

لینک گروه و کانال با `FOX_GROUP_URL` و `FOX_CHANNEL_URL` در `.env` قابل تغییرند.

## فرایند سفارش ساخت ویدیو

1. کاربر «ساخت ویدیو» را می‌زند؛ اگر مدیر ویدیوی پیش‌فرض تنظیم کرده باشد، اول همان ویدیو با متنش می‌آید، بعد پیام Bold معرفی.
2. **انتخاب نوع سفارش** (دکمه شیشه‌ای): «ساخت ویدیو با متن» (متن حداقل ۱۰۰ کاراکتر) یا «ساخت ویدیو با عکس» (عکس + متن توضیحی در کپشن).
3. انتخاب مدل با دکمه‌های شیشه‌ای (Inline Keyboard واقعی): `model plus` · `model fox` · `model acod`
4. انتخاب مدت و قیمت: «۱۰ ثانیه — ۳۵ هزار تومان» · «۲۰ ثانیه — ۶۰ هزار تومان» · «۳۰ ثانیه — ۸۰ هزار تومان» (کلیک مکرر سفارش تکراری نمی‌سازد؛ همان سفارش به‌روز می‌شود).
5. اطلاعات پرداخت از `.env` خوانده و Bold نمایش داده می‌شود؛ اگر `PAYMENT_GUIDE_IMAGE` فایلی موجود باشد همراه تصویر راهنما، وگرنه فقط متنی و بدون خطا. دکمه «📤 ارسال رسید» نمایش داده می‌شود.
6. کاربر بعد از زدن «ارسال رسید» عکس رسید را می‌فرستد (متن/فایل غیرعکس = راهنمایی). رسید فقط یک بار ثبت می‌شود و سفارش می‌رود به وضعیت «در انتظار بررسی پرداخت»؛ تا تأیید مدیر، پرداخت‌شده محسوب نمی‌شود.
7. رسید + جزئیات کامل Bold (نوع سفارش، متن درخواست، یوزرنیم یا نام نمایشی، کد شش‌رقمی، مدل، مدت، مبلغ) برای مدیر ارسال می‌شود؛ اگر ارسال ممکن نباشد، خطا در لاگ می‌آید و سفارش در صف «سفارش‌های در انتظار» می‌ماند.
8. بعد از **تأیید پرداخت**، ربات از مدیر تحویل می‌خواهد: دکمه «🎬 ارسال ویدیو» ← مدیر ویدیو را می‌فرستد ← همان ویدیو برای صاحب سفارش ارسال و سفارش `completed` می‌شود.

هر کاربر در اولین `/start` یک **شناسه شش‌رقمی یکتا و پایدار** می‌گیرد (با سفارش و شناسه چت API فرق دارد و جای آن استفاده نمی‌شود). داده‌ها در `data/bot.db` (SQLite) می‌مانند و با ری‌استارت پاک نمی‌شوند. وضعیت‌ها: `awaiting_receipt` ← `pending_review` ← `payment_approved` / `rejected` (و در ادامه `processing` و `completed`).

### دستورهای مدیر (فقط با `ADMIN_CHAT_ID`)

| دستور | عملکرد |
|---|---|
| (دکمه‌های ✅/❌ روی پیام رسید) | تأیید یا رد پرداخت همان سفارش + اطلاع به کاربر |
| `تأیید پرداخت <شماره سفارش>` / `رد پرداخت <شماره سفارش>` | همان کار به‌صورت متنی |
| (دکمه «🎬 ارسال ویدیو» بعد از تأیید) | تحویل ویدیوی نهایی به صاحب سفارش و تکمیل آن |
| `تحویل سفارش‌ها` | فهرست سفارش‌های تأییدشده منتظر تحویل با دکمه ارسال ویدیو |
| `سفارش‌های در انتظار` | صف سفارش‌های `pending_review` با دکمه تأیید/رد |
| `اعضا` | تعداد کل اعضا + کد شش‌رقمی، نام، یوزرنیم و شناسه‌های هر عضو |
| `<کد شش‌رقمی> مسدود` / `<کد شش‌رقمی> رفع مسدودیت` | مسدود/آزاد کردن کاربر؛ مسدود هیچ قابلیتی ندارد |
| `اطلاع رسانی` | گرفتن متن (با پشتیبانی **Bold**)، پیش‌نمایش و ارسال همگانی فقط پس از «تأیید ارسال» |
| `تنظیم ویدیو` | ربات ویدیو می‌گیرد، بعد متن همراهش را؛ برای همه کاربران ذخیره می‌شود (با `file_id`، دائمی) |
| `تنظیم متن ویدیو` | فقط متن همراه ویدیوی فعلی را عوض می‌کند |
| `حذف ویدیو` | ویدیوی پیش‌فرض را حذف و غیرفعال می‌کند |

پیدا کردن `ADMIN_CHAT_ID`: ربات را اجرا کنید، با حساب مدیر `/start` بفرستید و در لاگ Termux خط «شروع کاربر: splus_id=...» را بردارید؛ همان عدد را در `.env` بگذارید و ربات را ری‌استارت کنید.

## ساختار پروژه

```text
ai_new_plus/
├── main.py          # نقطه ورود: بررسی توکن (getMe)، ثبت دستورات رسمی، شروع Polling
├── config.py        # خواندن امن تنظیمات از متغیرهای محیطی
├── texts.py         # همه متن‌های فارسی و عنوان دقیق دکمه‌ها
├── keyboards.py     # ساخت ReplyKeyboardMarkup اصلی (۴ ردیف × ۲ دکمه)
├── bot_logic.py     # منطق خالص مسیریابی پیام‌های ساده (قابل‌آزمون بدون شبکه)
├── video_orders.py  # مدل‌ها، قیمت‌ها، متن پرداخت و وضعیت‌های سفارش ویدیو
├── image_orders.py  # ساخت تصویر: نوع/مدل، اعتبار روزانه و متن‌های سفارش تصویر
├── support.py       # پشتیبانی: پیام کاربر برای مدیر و پاسخ مدیر با ریپلای
├── storage.py       # SQLite: کاربران، کد شش‌رقمی، سفارش‌ها، اعتبار، پیام‌های پشتیبانی
├── handlers.py      # هندلرهای aiosplus: منو، سفارش ویدیو، رسید، مدیر و fallback
├── tests/           # آزمون‌های خودکار بدون نیاز به توکن واقعی
├── data/            # bot.db و فایل‌های زمان اجرا (در گیت نیست؛ با آپدیت حذف نمی‌شود)
├── requirements.txt
├── run.sh           # اجرای یک‌دستوره‌ای در Termux
├── .env.example     # نمونه تنظیمات بدون توکن واقعی
└── .gitignore
```

کتابخانه: [`aiosplus`](https://github.com/aminmadaniofficial/aiosplus) نسخه `0.1.0` روی **Bot API رسمی سروش‌پلاس** (`https://api.splus.ir/bot<token>/...`) با دریافت پیام از روش Long Polling (`getUpdates`). این پروژه ربات رسمی توکنی است و **یوزربات مبتنی بر ورود با شماره تلفن نیست**.

```bash
python -m unittest discover -s tests -v
```

آزمون‌ها ساختار و متن دقیق کیبوردها (اصلی و شیشه‌ای)، دستورهای `/start` و `/menu` و «منو»، کد شش‌رقمی پایدار و یکتا، انتخاب مدل/مدت و مبلغ دقیق، ضدتکرار بودن سفارش و رسید، صف و تأیید مدیر، جدایی سفارش کاربران، تنظیم ویدیوی دائمی و نبودِ توکن/اطلاعات حساس در سورس را بررسی می‌کنند.

## عیب‌یابی

| پیام/وضعیت | علت و راه‌حل |
|---|---|
| «توکن ربات پیدا نشد» | فایل `.env` ساخته نشده یا `BOT_TOKEN` خالی است: `cp .env.example .env` و ویرایش آن |
| «توکن ربات نامعتبر است» | توکن اشتباه یا باطل شده؛ از BotFather توکن تازه بگیرید و فقط در `.env` بگذارید |
| خطای شبکه هنگام اجرا | اتصال اینترنت Termux را بررسی کنید؛ ربات در حلقه دریافت پیام، اتصال را خودکار دوباره تلاش می‌کند |
| ربات پاسخ نمی‌دهد و نمونه دیگری در حال اجراست | فقط یک نمونه از ربات را هم‌زمان اجرا کنید |
| منو نمایش داده نمی‌شود | یک بار `/start` بفرستید؛ اگر کیبورد بسته شده، دستور «منو» را ارسال کنید |

## برندینگ

سبک بصری «روباه» با ایموجی 🦊 و پیام‌های کوتاه و مرتب پیاده شده است (پالت پیشنهادی برند: نارنجی، سفید و خاکستری تیره). توجه: Bot API سروش‌پلاس امکان تعیین **رنگ واقعی** دکمه‌های Reply Keyboard را نمی‌دهد؛ بنابراین ادعا نمی‌شود دکمه‌ها نارنجی هستند و حس رنگی فقط از متن و ایموجی ساخته می‌شود. عنوان دکمه‌ها عیناً همان متن‌های خواسته‌شده است و برای حفظ تطابق دقیق، به آن‌ها ایموجی اضافه نشده است.

## نقشه راه (هنوز پیاده‌سازی نشده)

اتصال API واقعی تولید ویدیو/تصویر، اعتبار رایگان و نمونه‌ها در مراحل بعد اضافه می‌شوند. تا آن زمان انجام سفارش ویدیو بعد از تأیید پرداخت، خودکار نیست.
